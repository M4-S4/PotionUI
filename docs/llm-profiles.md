# LLM Capability Profiles

Every LLM configuration resolves to a **capability profile**: what the model behind it can
do and which quirks the request has to respect (tool choice limits, rejected sampling
parameters, how reasoning is switched and replayed, prompt cache minimums, context window).
Core never branches on the configuration's type; adapters and the turn engine read the
profile instead.

A profile is built in three layers, later layers winning field by field:

1. **Seed** — `src/std/llm/profiles.yml`, picked by adapter name and model name.
2. **Discovered** — what the adapter learns from the server (`Adapter.discover`): Anthropic
   `GET /v1/models` capabilities, Ollama `/api/show`, OpenRouter `supported_parameters`, and
   so on. Cached in memory for an hour; a failed discovery is remembered for five minutes and
   never breaks a request.
3. **Override** — what an admin set on the configuration (`llm_configurations.profile_overrides`).

Every field remembers the layer that set it (`seed`, `discovered` or `override`).

## The seed table

`profiles.yml` has five top-level keys.

| Key | Holds |
|---|---|
| `version` | Always `1`. |
| `sources` | Name → public documentation URL. Every curated row cites at least one. YAML comments are not used; the citation is data. |
| `base` | The conservative floor. It sets **every** profile field, so an unknown adapter or model still has a complete profile. |
| `rows` | Curated rows. A row has an `id`, its `source` names, optional `adapters`, `models` (regular expressions, case-insensitive, searched in the lowercased model name) and `servers`, and `fields`. |
| `catalog` | Generated by `scripts/llm_profiles_refresh.py` from the models.dev model list: exact model ids with their context window, output limit, prices, vision, tools, reasoning control and rejected temperature. Last key in the file. |

Resolution applies `base`, then the catalog entry for the exact (adapter, model), then every
matching row in file order. Curated rows therefore win over the catalog, and must not set
`context_window`, `max_output_tokens` or `prices`, which belong to the catalog. Ollama models
are never in the catalog: their usable context is the loaded context (VRAM and `num_ctx`),
not the trained maximum, and comes from discovery or an override.

`servers` narrows a row to configurations whose `provider_options.server` names it
(for example `vllm`). It exists because an OpenAI-compatible base URL says nothing about the
software behind it.

Refresh the catalog with:

```bash
python scripts/llm_profiles_refresh.py            # fetch https://models.dev/api.json and rewrite the catalog
python scripts/llm_profiles_refresh.py --input api.json
python scripts/llm_profiles_refresh.py --check    # exit 1 when the catalog is stale
```

The script only rewrites the `catalog` key; everything above it is kept byte for byte.

## Fields

| Field | Meaning |
|---|---|
| `context_window`, `max_output_tokens` | Token limits. `null` means unknown. |
| `tools`, `prompt_tools`, `parallel_tools`, `strict_tools` | Native tool calling, tools rendered into the prompt as XML, several calls per step, strict schemas. |
| `tool_choice`, `tool_choice_with_reasoning` | Allowed modes (`auto`, `none`, `required`, `named`) without and with reasoning on. Never force a mode that is not listed. |
| `tool_id_rule` | `passthrough` the wire's ids, `mint` ids (Ollama has none), or `nine_digits`. |
| `structured_output` | `native` schema support, via a `tool`, or `prompted` JSON. |
| `reasoning` | The primary control: `none`, `toggle` (on/off), `effort` (graded, see `reasoning_levels`), `budget` (token budget), `always_on`. |
| `reasoning_levels` | Accepted effort values, in order. |
| `reasoning_toggle` | Where the on/off switch lives (`think`, `thinking.type`, `chat_template_kwargs.enable_thinking`, `reasoning.effort`). `null` on an `effort` model means thinking cannot be turned off. |
| `reasoning_field` | The response and request field carrying reasoning text (`reasoning_content`, `reasoning`, `thinking`). `null` means echo what the server sent. |
| `replay` | See below. |
| `interleaved_reasoning` | The model reasons between tool calls. |
| `vision`, `max_images`, `tool_result_media` | Image input, images per request, media inside tool results. |
| `sampling_rejected`, `sampling_ignored_with_reasoning` | Parameters that make the API answer 400, and parameters it silently ignores while reasoning. Subset of `temperature`, `top_p`, `top_k`, `min_p`. |
| `cache`, `cache_min_tokens` | `none`, `automatic`, `explicit` (the client must mark breakpoints) or `local_prefix`, and the shortest cacheable prefix. |
| `prices` | USD per million tokens: `input`, `output`, `cached_input`, `cache_write`, `reasoning`. |
| `verified` | Set by the chat evaluation, read-only. |

## Reasoning replay

`harness/replay.py` implements the `ReplaySelector` port as `policy_replay(steps, turn_id=,
target=, profile=)`. It returns the messages to render and the notices to show.

| Policy | Turn in progress | Earlier turns |
|---|---|---|
| `send_all` | kept | kept; the provider or the chat template filters what it does not need |
| `preserve` | kept | kept, and the adapter also sets the template flag that stops the template dropping it (Qwen3.5/3.6 `preserve_thinking`, GLM `clear_thinking: false`, Kimi `thinking.keep: "all"`, llama.cpp `--reasoning-preserve`) |
| `drop_earlier` | kept | dropped |
| `never` | dropped | dropped (wires with no reasoning input) |

`send_all` is the default. The seed picks `drop_earlier` where the model's own template drops
earlier reasoning anyway, which keeps the context budget honest: Qwen3, Qwen3.5/3.6, gpt-oss
and the native engine. DeepSeek needs `send_all`: with tools in the request, every earlier
`reasoning_content` must be passed back or the API answers 400.

Reasoning that carries provider data (`ReasoningPart.opaque`, such as signatures and
encrypted content) can only be read by the origin that produced it. When the target differs
by adapter, provider, model or credential, such parts are left out of that request, a
`reasoning_dropped` notice names the model or API key, and the stored steps stay untouched, so
switching back restores them. Plain reasoning text travels to any target. Whenever a message
is changed, its verbatim `raw` payload is discarded so an adapter cannot replay what was
removed.

Tool calls made by another origin lose their provider data and get `opaque =
{"placeholder_signature": True}`. Adapters whose wire demands a signature (Gemini) substitute
their documented placeholder when they see it.

`missing_reasoning(messages)` lists the assistant messages that carry no reasoning. An adapter
for a provider that needs reasoning replayed whenever tools are present (DeepSeek) switches
thinking off for that request when the list is not empty.

## Admin routes

All admin only.

| Route | Does |
|---|---|
| `GET /api/llm/profile/schema` | The editable fields: `name`, `kind` (`enum`, `set`, `int`, `bool`, `list`, `text`, `prices`, `verification`), `label`, `group`, and `options`, `min`, `nullable`, `readonly` where they apply. |
| `GET /api/llm/configurations/{id}/profile` | The profile with, per field, the effective `value`, its `source`, and the `seed`, `discovered` and `override` values. Runs discovery first when nothing is cached. |
| `PUT /api/llm/configurations/{id}/profile` | `{"overrides": {"replay": "preserve", "context_window": null}}`. Merges into the stored overrides; `null` clears one. Validated against the schema. |
| `POST /api/llm/configurations/{id}/profile/refresh` | Runs discovery again and returns the profile. A failed discovery keeps the previous result and reports `discovery_error`. |

Editing the configuration itself never touches its overrides.

## Writing an adapter

An adapter reads the profile it is handed and never inspects the configuration's `type`.
`Adapter.discover(config)` returns a `ProfileLayer` of discovered fields; unknown fields or
wrongly typed values reject the whole layer and show up as the profile's `discovery_error`.
