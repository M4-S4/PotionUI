# LLM Capability Profiles

Every LLM configuration resolves to a **capability profile**: what the model behind it can
do and which quirks the request has to respect (tool choice limits, rejected sampling
parameters, how reasoning is switched and replayed, prompt cache minimums, context window).
Core never branches on the configuration's type; adapters and the turn engine read the
profile instead.

A profile is built in three layers, later layers winning field by field:

1. **Seed** — the profile files under `content/llm-profiles/` (see [Where profiles live](#where-profiles-live)), picked by adapter name and model name.
2. **Discovered** — what the adapter learns from the server (`Adapter.discover`): Anthropic
   `GET /v1/models` capabilities, Ollama `/api/show`, OpenRouter `supported_parameters`, and
   so on. Cached in memory for an hour; a failed discovery is remembered for five minutes and
   never breaks a request.
3. **Override** — what an admin set on the configuration (`llm_configurations.profile_overrides`).

Every field remembers the layer that set it (`seed`, `discovered` or `override`).

## Where profiles live

Seed rows are content, configured like presets and recipes. Only the contract stays in core:
`src/std/llm/profile_base.yml` holds the `base` floor, and the schema is `profile_schema.py`.

| Root | Path | Notes |
|---|---|---|
| Base | `src/std/llm/profile_base.yml` | The `base` key only. A broken base file fails startup. |
| Marketplace | `content/llm-profiles/marketplace/*.yml` | Shipped, tracked. One file per provider family (`anthropic`, `openai`, `gemini`, `ollama`, `vllm`, `native`). |
| Plugins | the plugin's `llm_profiles:` roots | Scanned only while the plugin is enabled. |
| Local | `content/llm-profiles/local/*.yml` | Yours, `.gitignore`d. |

Roots apply in that order, files within a root by name. Rows are keyed by `id`: a row whose `id`
already exists in an earlier root **replaces** that row (it does not merge into it) and keeps its
place in the order. Catalog entries are keyed the same way by (adapter, model). The discovery and
override layers described above are unchanged and still sit on top of the seed.

Rows with `servers` apply after rows without, whichever root they come from, so a server-specific
row still wins over an adapter-wide one that a plugin contributes.

Every file is validated when it loads. A file that is not valid YAML, has the wrong `version` or
unknown top-level keys is skipped whole; a row that fails validation is skipped on its own and the
rest of the file still loads. Each rejection is logged as a warning naming the file path, and a
broken local file never affects chat. Edits to a local or plugin file are picked up on the next
request.

### Adding a local row

Create `content/llm-profiles/local/mine.yml`. It carries the `sources` it cites, since a row can only
cite sources defined in its own file:

```yaml
version: 1
sources:
  my-model-card: https://example.org/my-model
rows:
  - id: my-model
    source: [my-model-card]
    adapters: [openai-chat]
    models: ['(^|/)my-model']
    fields:
      vision: true
      reasoning_field: reasoning_content
```

Reuse the `id` of a shipped row to replace it.

### Shipping rows from a plugin

Declare a root in `manifest.yml`; the directory is scanned for `*.yml` files in the same format
(see [Plugin API](plugin-api.md#contributing-llm-profile-rows)):

```yaml
llm_profiles:
  - path: "profiles"
```

The `deepseek-provider` plugin ships the DeepSeek rows and catalog entries this way.

## The profile file

Each file has these top-level keys.

| Key | Holds |
|---|---|
| `version` | Always `1`. |
| `sources` | Name → public documentation URL. Every curated row cites at least one, defined in the same file. YAML comments are not used; the citation is data. |
| `models_dev` | Optional. Maps a models.dev provider to the adapter its models run on (`anthropic: anthropic-messages`). The refresh script rebuilds the `catalog` of files that declare it. |
| `rows` | Curated rows. A row has an `id`, its `source` names, optional `adapters`, `models` (regular expressions, case-insensitive, searched in the lowercased model name) and `servers`, and `fields`. |
| `catalog` | Generated by `scripts/llm_profiles_refresh.py` from the models.dev model list: exact model ids with their context window, output limit, prices, vision, tools, reasoning control and rejected temperature. Last key in the file. |

The base file has `version` and `base` instead. `base` is the conservative floor: it sets **every**
profile field, so an unknown adapter or model still has a complete profile.

Resolution applies `base`, then the catalog entry for the exact (adapter, model), then every
matching row in the order above. Curated rows therefore win over the catalog, and must not set
`context_window`, `max_output_tokens` or `prices`, which belong to the catalog. Ollama models
are never in the catalog: their usable context is the loaded context (VRAM and `num_ctx`),
not the trained maximum, and comes from discovery or an override.

`servers` narrows a row to configurations whose profile `server` names it (for example
`vllm`). An OpenAI-compatible base URL says nothing about the software behind it, so the
server is a profile field: the adapter's discovery sets it (vLLM lists `owned_by: "vllm"` in
`/v1/models`) and an admin can override it. The override wins, then the discovered value, and
the seed rows for that server apply underneath. Rows and the catalog cannot set `server`
themselves.

Refresh the catalog with:

```bash
python scripts/llm_profiles_refresh.py            # fetch https://models.dev/api.json and rewrite the catalogs
python scripts/llm_profiles_refresh.py --input api.json
python scripts/llm_profiles_refresh.py --check    # exit 1 when a catalog is stale
python scripts/llm_profiles_refresh.py --seed content/llm-profiles/marketplace/openai.yml
```

The script rewrites every shipped file that declares `models_dev` (the marketplace files and the
`llm_profiles` roots of the plugins under `content/plugins/marketplace/`, enabled or not). It only rewrites the `catalog`
key; everything above it is kept byte for byte. `--seed` limits it to the named files.

## Fields

| Field | Meaning |
|---|---|
| `context_window`, `max_output_tokens` | Token limits used for budgeting. `null` means unknown. |
| `context_request` | The context size to request from servers that allocate it per request (Ollama `num_ctx`). Ollama discovery sets it to the window it reports (the Modelfile `num_ctx`, or the trained length capped at 32768 so a huge default is never allocated as a KV cache on a GPU shared with image generation), so the window the budget plans with is the one the server loads. A seed row or an admin override wins over the discovered value, and when it is smaller than `context_window` the budget plans with it. |
| `tools`, `prompt_tools`, `parallel_tools`, `strict_tools` | Native tool calling, tools rendered into the prompt as XML, several calls per step, strict schemas. |
| `tool_choice`, `tool_choice_with_reasoning` | Allowed modes (`auto`, `none`, `required`, `named`) without and with reasoning on. Never force a mode that is not listed. |
| `tool_id_rule` | `passthrough` the wire's ids, `mint` ids (Ollama has none), or `nine_digits`. |
| `structured_output` | `native` schema support, via a `tool`, or `prompted` JSON. |
| `reasoning` | The primary control: `none`, `toggle` (on/off), `effort` (graded, see `reasoning_levels`), `budget` (token budget), `always_on`. |
| `reasoning_levels` | Accepted effort values, in order. |
| `reasoning_toggle` | Where the on/off switch lives (`think`, `thinking.type`, `chat_template_kwargs.enable_thinking`, `reasoning.effort`). `null` on an `effort` model means thinking cannot be turned off. |
| `reasoning_field` | The response and request field carrying reasoning text (`reasoning_content`, `reasoning`, `thinking`). `null` means echo what the server sent. |
| `server` | The software behind an OpenAI-compatible endpoint (`vllm`, ...). Discovered or overridden; it selects `servers` rows. |
| `replay` | See below. |
| `replay_required_with_tools` | The API rejects a request with tools unless every earlier assistant message carries its reasoning (DeepSeek). |
| `reasoning_prefix_bound` | Reasoning is only valid while everything before it is unchanged (Anthropic). |
| `interleaved_reasoning` | The model reasons between tool calls. |
| `vision`, `max_images`, `tool_result_media` | Image input, images per request, media inside tool results. |
| `sampling_rejected`, `sampling_ignored_with_reasoning` | Parameters that make the API answer 400, and parameters it silently ignores while reasoning. Subset of `temperature`, `top_p`, `top_k`, `min_p`. |
| `recommended_sampling` | The model card's sampling values (thinking mode where the card distinguishes). The lowest sampling layer. |
| `cache`, `cache_min_tokens` | `none`, `automatic`, `explicit` (the client must mark breakpoints) or `local_prefix`, and the shortest cacheable prefix. |
| `prices` | USD per million tokens: `input`, `output`, `cached_input`, `cache_write`, `reasoning`. |
| `verified` | Set by the chat evaluation, read-only. |

## Reasoning replay

`harness/replay.py` implements the `ReplaySelector` port as `policy_replay(steps, turn_id=,
target=, profile=)`. It returns the messages to render and the notices to show.

| Policy | Turn in progress | Earlier turns |
|---|---|---|
| `send_all` | kept | kept; the provider or the chat template filters what it does not need |
| `preserve` | kept | kept, and the adapter also sets the template flag that stops the template dropping it (Qwen3.5/3.6 `preserve_thinking`, GLM `clear_thinking: false`, Kimi `thinking.keep: "all"`, llama.cpp `--reasoning-preserve`) |
| `drop_earlier` | kept | dropped |
| `never` | dropped | dropped (wires with no reasoning input) |

`send_all` is the default. The seed picks `drop_earlier` where the model's own template drops
earlier reasoning anyway, which keeps the context budget honest: Qwen3, Qwen3.5/3.6, gpt-oss
and the native engine. DeepSeek needs `send_all`: with tools in the request, every earlier
`reasoning_content` must be passed back or the API answers 400.

Reasoning that carries provider data (`ReasoningPart.opaque`, such as signatures and
encrypted content) can only be read by the origin that produced it. When the target differs
by adapter, provider, model or credential, such parts are left out of that request, a
`reasoning_dropped` notice names the model or API key, and the stored steps stay untouched, so
switching back restores them. Plain reasoning text travels to any target. Whenever a message
is changed, its verbatim `raw` payload is discarded so an adapter cannot replay what was
removed.

Tool calls made by another origin lose their provider data and get `opaque =
{"placeholder_signature": True}`. Adapters whose wire demands a signature (Gemini) substitute
their documented placeholder when they see it.

`missing_reasoning(messages)` lists the assistant messages that carry no reasoning.
`must_disable_reasoning(profile, messages, tools_present)` is true when the profile has
`replay_required_with_tools`, the request carries tools and that list is not empty; the engine
then turns reasoning off for that request and tells the user, instead of sending a request the
API would answer with 400.

`policy_replay(..., prefix_changed_at=seq)` takes the sequence number of the earliest step that
was trimmed or replaced by a compaction. For a `reasoning_prefix_bound` profile, every assistant
step after it loses its reasoning and its raw payload (Anthropic invalidates a thinking block
once anything before it changes) and a `reasoning_dropped` notice with the reason
`history_changed` is returned.

## Sampling and reasoning settings

`harness/sampling.py` `resolve_settings(config, profile, request)` turns the layers into the
`Settings` an adapter renders. For each of `temperature`, `top_p`, `top_k` and `min_p` the first
value that is set wins: the request, then `provider_options`, then the configuration (only
`temperature` is a column), then the profile's `recommended_sampling`. `max_tokens` follows the
same order without a recommendation. Parameters in `sampling_rejected` are then removed.
`provider_options.reasoning_effort`, `think` and `thinking` map to the one `Settings.reasoning`
value (`reasoning_effort: "none"` becomes `False`); a request value wins over all of them.

## Admin routes

All admin only.

| Route | Does |
|---|---|
| `GET /api/llm/profile/schema` | The editable fields: `name`, `kind` (`enum`, `set`, `int`, `bool`, `list`, `text`, `prices`, `verification`), `label`, `group`, and `options`, `min`, `nullable`, `readonly` where they apply. |
| `GET /api/llm/configurations/{id}/profile` | The profile with, per field, the effective `value`, its `source`, and the `seed`, `discovered` and `override` values. Runs discovery first when nothing is cached. |
| `PUT /api/llm/configurations/{id}/profile` | `{"overrides": {"replay": "preserve", "context_window": null}}`. Merges into the stored overrides; `null` clears one. Validated against the schema. |
| `POST /api/llm/configurations/{id}/profile/refresh` | Runs discovery again and returns the profile. A failed discovery keeps the previous result and reports `discovery_error`. |

Editing the configuration itself never touches its overrides.

## Sampling columns

A configuration's `temperature` and `max_tokens` are optional. `NULL` means the model's
recommended value (`recommended_sampling`), else nothing is sent. Migration 069 rebuilt
`llm_configurations` so both columns allow `NULL`, cleared every `temperature` still at the old
`0.7` default, and moved `provider_options.context_window`, `num_ctx` (Ollama) and
`force_prompt_tools` into `profile_overrides` (`context_window` and `context_request`,
`prompt_tools`). `timeout` stays required.

## Writing an adapter

An adapter reads the profile it is handed and never inspects the configuration's `type`.
`Adapter.discover(config)` returns a `ProfileLayer` of discovered fields; unknown fields or
wrongly typed values reject the whole layer and show up as the profile's `discovery_error`.
